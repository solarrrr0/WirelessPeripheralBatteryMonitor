# Phase 3：ATK 可选自动刷新设计

日期：2026-10-23（Asia/Shanghai）。状态：**软件实现已接线，候选验证结果以开发日志最新记录为准；未执行自动实机查询**。用户选择“ATK 可选自动刷新（默认关闭）”。下文为本次实现依据，第9节NotRun保留设计时状态，实际软件检查结果另记，不改写为实机通过。

## 1. 起点与本轮范围

沿用 `Phase2-20261022-185012-9f1d8914` 的手动托盘链路：`AtkProtocol`、精确接口策略、`Win32AtkHidTransport`、`AtkManualSession`、`AtkTraySession` 和现有总图标。此前包外实机取得 95%，用户核对官网同次一致；事实范围见 [ATK 实机记录](ATK_LIVE_VALIDATION.md)。该结果不能证明周期查询、官网共存或异常恢复已通过。

下一次实现交付一个可试用版本：设置中显式启用 ATK 自动刷新，默认每 5 分钟查询；手动按钮继续可用，两者共享查询占用、响应验收和历史值。关闭功能、Mock、诊断及旧资源测量入口均不产生自动 HID 查询。

设计轮仅修改文档；用户随后要求“下一步”，已开始本规格的软件实现、假传输验证及独立候选交付。实施轮不枚举或查询真实设备，不运行 Computer Use。耳机在线 GATT、自启、独立设备图标、低电量提醒继续按各自阶段推进。

## 2. 用户操作与默认行为

设置窗口保留 Windows 系统报告的 1–30 分钟周期，另加 ATK 区域，避免同一个数字同时改变两条来源：

| 控件 | 默认与行为 |
| --- | --- |
| 自动读取 ATK Duckbill Ultra 电量 | 未勾选；配置缺失、损坏、版本未知时也关闭 |
| ATK 刷新间隔 | 整数 5–30 分钟，默认 5；与 Windows 周期独立 |
| 说明 | “启用后及下次启动时会自动查询接收器。使用 ATK 官网或驱动时可先关闭。” |
| 应用 | 整份配置保存成功后生效；关闭或取消窗口不更改运行状态 |

启用并应用后第一次查询延迟 10 秒，列表显示等待状态；后续启动若已保存启用，也在消息循环可用后等待 10 秒。仅打开设置、修改未保存控件或修改周期不立即查询。修改周期从应用时刻重新等待新周期；失败退避和最小间隔仍取更晚的限制。

菜单和列表保留“读取 ATK 电量”，增加“ATK 自动刷新：关闭 / 已开启 / 等待重试 / 已暂停”。需要人工处理的阻断给出原因；不每轮弹窗。普通“刷新”和打开列表不额外启动 HID；只有自动到期和专用手动按钮触发。

关闭自动刷新立即撤销已排队的自动请求。无在途批次时，已有成功值继续按原 5 分钟时效显示；正在查询时取消本批、使其结果失效并等待收尾。手动读取不因自动开关关闭而被永久禁用，协议或收尾阻断除外。

## 3. 唯一批次与响应验收

新增生产用 `AtkBatterySession`，承接当前 `AtkTraySession` 的读取和展示状态；手动和自动调用同一个 `TryRead(reason)`。`AtkManualSession` 与独立研究宿主保留候选观测用途，不将其 `AcceptedPercent=null` 改成正式兼容声明。两种宿主仍由既有单实例规则互斥。

生产批次复用原生传输和编解码，顺序固定为：

1. 扫描本轮接口；只接受唯一精确目标且检查错误为零。
2. 打开该目标，并复用原生传输对实际句柄的再次核验。
3. 在线 `0x03` 验收通过且字段为 1，才查询型号 `0x10`。
4. 型号验收通过且 CID/MID 为 1/2，才查询电量 `0x04`。
5. 电量验收通过、连接释放成功且批次仍有效，才提交百分比。

目标限定为接收器 `373B:11FD`、MI01、Usage `FF02:0002`、Input/Output 各 17 字节且两者均声明 Report ID 8。当前实机 Feature 为 0；本次生产策略也要求为 0，不能把现有 `AtkHidPolicy` 未检查 Feature 长度误写成已检查。不同能力直接拒绝，不轮流试写其他 collection，也不从接收器 ID 推断鼠标型号。

**每条回复在进入下一命令前**核对完整长度、报告 ID、命令、非请求回显、声明数据长度、原始状态 0、全帧和模 256 为 `0x55`。在线字段只认 0/1；合法 0 表示本次未在线，提前结束。型号只认目标 1/2；其他型号停止。电量声明至少 2 字节，百分比为 0–100（含合法 0%）；仅声明至少 4 字节才保留电压原始字段。充电仍显示未知。

这是目标已观测格式的接纳约束，不是所有固件成功码/校验语义的通用定义。当前 `AtkTraySession` 在三回复结束后才统一检查状态/校验，生产重构须将检查前移；不能只给原手动方法外套周期 timer。

同一批次每个操作码至多调用一次，不补发。扫描、打开和三次查询共用从批次开始计算的 **10 秒逻辑期限**；不再让扫描和读取各获得新的 10 秒预算。超期立即禁止后续命令及结果提交；原始操作仍保留占用直到真实终态和清理完成。

## 4. 调度与状态

新增 `AtkRefreshController`，只计算下一次时刻、响应用户动作并驱动上述唯一批次。控制器由 UI 线程拥有，注入 `TimeProvider` 和 UI 派发函数。采用单次 `ITimer`（period 为 Infinite），回调只投递消息，不在回调线程直接执行 HID 或修改控件。API 依据见第 10 节。

每次重排先递增 timer 版本，已投递旧回调在 UI 端校验版本后退出；状态、查询占用和功能开关仍须二次检查。timer 释放不被当作已投递 UI 消息全部消失的证明。

| 状态 | 进入原因 | 到期/用户动作 |
| --- | --- | --- |
| ManualOnly | 默认或自动关闭 | 不安排自动 timer；允许合规手动读取 |
| Scheduled | 已启用并等待首次或下一周期 | 到期且无占用时开始一批 |
| Reading | 扫描、打开、查询或清理中 | 重复点击/到期均合并到当前批次，不排尾随批次 |
| Backoff | 完全收尾的无接口、合法离线或无发送的暂时错误 | 按退避安排下一批；显示原因和剩余等待 |
| Blocked | 协议不符、不同型号、多目标、查询后异常或清理失败 | 自动及手动均停止；切换开关不清除，退出重启后再评估 |
| Draining | 已超期/取消而原始操作仍未终态 | 保留占用，不安排下一次查询；晚值丢弃 |
| Suspended | 收到系统暂停 | 撤销 timer、旧值失效、取消批次 |
| Stopped | 应用退出 | 永久拒绝新任务和迟到提交 |

`AutoEnabled` 与阻断/暂停分开保存：开关为真不等于当前允许查询。状态优先级为 Stopped、Suspended、Draining、Blocked、Reading、Backoff/Scheduled、ManualOnly。Draining 结束后按保存的阻断原因进入 Blocked，不能自动回 Scheduled。

正常成功后，下次自动时间为**批次完全收尾时刻 + 配置周期**。手动成功替换原自动到期时间，避免紧接着又自动读取。自动关闭时手动成功不创建查询 timer，仅保留时效回调。

所有批次共用最小启动间隔 10 秒，按单调时间计算。错过的自动周期不补跑；忙碌中收到到期或重复点击不建立计数队列。一次 timer 同时选取下一个查询到期、值过期或活动批次逻辑期限中最早者；只执行对应动作，时效到期不会触发提前查询。等待期间不保留 HID 句柄，不以常驻 50ms/1s 循环检查状态。

## 5. 失败、共存与恢复

设配置周期为 P，连续可恢复失败次数 n 从 1 起，下一次自动等待为 `min(30 分钟, P × 2^(n-1))`，实现时用饱和计算。P=5 时为 5、10、20、30、30 分钟。只有完整成功重置失败计数；关闭再开启、保存设置或系统恢复均不清零既有退避/阻断。

| 结果 | 处理与重试范围 |
| --- | --- |
| 无匹配接口；合法在线字段 0 | 本次无当前值，历史标“上次”；完全收尾后退避 |
| 元数据异常或打开被拒绝，确认未调用任何 QueryAsync，且已完全收尾 | 可退避；权限/共享冲突仅描述为可能占用，不能断言某个驱动正在运行 |
| 多个目标、型号不符、未知状态/校验/字段 | 阻断；不猜选、不继续发命令 |
| QueryAsync 已调用后发生超时、取消或异常；无法确认是否发出 | 保守认定可能已有设备请求，先 Draining，随后阻断；不自动创建新会话重试 |
| 清理失败或原始任务未结束 | 保留占用并阻断；不能用逻辑超时、Dispose 调用或新 transport 绕开 |

批次结果须包含枚举原因、`QueryMayHaveStarted`、原始任务/清理终态。`QueryMayHaveStarted` 在调用任一 `QueryAsync` **之前**置真，不把已收到响应计数或本地 task 状态误当成“绝未发送”的证明。生产路径只在这个标记为假且完整清理成功时，将访问拒绝等归为可恢复。

手动按钮可绕过一次常规离线/无接口退避，以便用户唤醒鼠标后刷新；仍遵守 10 秒间隔、原始占用和所有阻断。手动失败同样累计退避，不触发紧随重试。

现有共享句柄和 `HidD_FlushQueue` 保留；不新增排他抢占、结束官网/厂商进程或设备配置命令。协议没有已验证的每请求唯一关联标识，队列清空也不能证明其他程序迟到回复已消失。因此单批命令匹配和本应用代次校验不能完全排除官网同协议回复串入；自动共存须实测，试用说明建议官网操作期间关闭自动刷新。超时后自动重开并非本版恢复策略。

暂停先递增批次/timer 代次，再取消与失效当前值。恢复仅在自动仍启用、无阻断且旧任务全部结束时重新排期：至少延迟 10 秒，并保留尚未到期的退避/最小间隔。暂停时若可能已有请求，保留上述阻断；不因为收到 Resume 就清除。自动关闭时恢复不查询。暂不新增 USB 热插拔 watcher，无接口通过低频退避复查；拔出导致进行中的请求失败时按查询后异常处理。

## 6. 时效、展示和诊断

成功电量固定 **5 分钟有效**，不随设置延长；从电量回复完成时的单调时间计算，UTC 只用于显示。完成清理后才提交，但不能将清理结束时间当作回复时间来延长时效。正在新批次、失败、暂停、超期或退出时退出当前聚合；历史保留原百分比和读取时间，不变成 0%。

P=5 时，旧值过期到新批成功之间允许短暂显示“上次”；P>5 时会有更长历史区间。这是明确的数据时效取舍，不以延长旧读数资格填满图标。列表写明“接收器读取（手动/自动）”、时间、自动状态和充电未知；总图标只合并仍有效的值，隐藏列表继续按需渲染。

当前正常诊断仅捕获 Coordinator，ATK 值由 App 附加，不能声称已包含 ATK。实现时新增固定白名单 `AtkDiagnosticSummary`：开关、周期、运行状态、枚举原因、批次/操作开始及终态数、超时/清理错误数、当前/上次百分比及时间。不导出设备路径、唯一 ID、RF ID、原始报文或异常自由文本；读取摘要不触发设备 I/O。

摘要接入现有用户主动导出、256KiB JSON 限额和合法缩减过程；单一 ATK 摘要不单独建立持续日志文件。诊断 schema 如需增加字段同步升级；旧报告不回写，计数不能解释为无线包数。退出报告合并 ATK 未收尾及清理结果。

## 7. 配置与模式隔离

`PollingSettingsStore` 迁移为 schemaVersion 2，保留 `pollIntervalMinutes` 和未知字段，新增一个有界结构：

```json
{
  "schemaVersion": 2,
  "pollIntervalMinutes": 5,
  "atk": { "autoRefreshEnabled": false, "pollIntervalMinutes": 5 }
}
```

schema 1 在内存中按 ATK 关闭/5 分钟迁移，只有显式应用才写盘；当前读取 schema 1 的旧版应用遇到 schema 2 会进入不支持/不可保存状态，不会悄悄覆盖。schema 2 要求两个 ATK 字段类型/范围正确；缺少 atk 整体时按关闭/5 分钟处理，atk 存在但字段不完整、重复键、非法类型或越界则整份配置保留并禁止保存，采用默认值且自动关闭。检查已知结构的重复键，限制沿用 64Ki 字符/深度 16。

保存使用现有同目录原子替换，整体成功后一次更新运行状态。失败保留磁盘与运行开关/周期；打开窗口或启动加载不自动改写。配置只保存设置，不保存电量、接口路径、接收器身份、95%历史样本或运行时阻断。无配置默认关闭；明确保存 true 才允许下次正常启动自动查询。

Mock、自测、独立 Windows/GATT/ATK 观测宿主均不能读取真实启用配置并创建自动控制器。现有 `--measurement-report` 在 Program 中排除了 ATK，继续保持该口径；它的结果只代表 Windows 属性场景。未来自动 ATK 资源观测另设显式入口和场景标签，不能借旧入口/旧内存数字宣称自动版达标。

## 9. 必要验证与实机门槛

软件新增只设下列 6 组行为检查，复用现有假传输/假时间/实际自有控件，不复制大量实现镜像断言。均为 **NotRun**：

| 编号 | 要验证的行为 |
| --- | --- |
| AA01 | 默认/旧配置/损坏/未来配置不自动 I/O；schema 2 保存、重载、未知字段、嵌套重复键和保存失败不半生效；Mock/诊断/旧测量隔离 |
| AA02 | 启用后 10 秒首查，成功后按周期；手动/到期竞争只一批、无尾随；调周期/关开/旧回调不绕间隔；无高频空闲检查 |
| AA03 | 精确能力和逐回复早停：错误状态/校验在线回复不得发送型号，错误型号回复不得发电量；合法 0% 和两字节电量；扫描到清理统一期限 |
| AA04 | 离线/无接口退避至上限，成功重置；无发送访问拒绝可恢复；已可能发送的超时/取消/异常与清理失败不能自动重开，晚终态/晚值被隔离 |
| AA05 | 实际托盘/设置与生产投影：开关保存、来源/时间、5分钟边界、P>5历史区间、最低图标、普通刷新不查HID、隐藏列表不反复渲染 |
| AA06 | 暂停/恢复/关闭/退出及已排队回调竞态；全应用共用退出预算；白名单诊断/大小限制与 ATK 开始终态/未收尾计数一致 |

有实现后将这 6 组加入现有有效测试入口，同一次候选构建执行 Core、平台、App、Mock 与发布必要回归，报告绑定 BuildId/二进制。无新增变化或失败不重复全部测试，不为本轮设计重跑旧用例。

实机验收另列下列 4 项，全部 **NotRun**，不能用假传输代替：

| 门槛 | 一次集中试用要记录的证据 |
| --- | --- |
| AL1 | 用户实际启用/关闭与重启加载；同构建正常托盘取得目标百分比，和可比较时刻的官网读数核对；至少三个正常周期确认次数/间隔 |
| AL2 | 官网/厂商软件使用前后及必要并行场景，检查冲突、错误串入或超时；无法证明关联时保留限制，不宣布稳定共存 |
| AL3 | 鼠标休眠、接收器拔插、真实系统暂停/恢复和查询中关闭；不假0%、不叠请求、按阻断/退避规则收尾；人工系统操作依当次授权 |
